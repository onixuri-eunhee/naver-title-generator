# 작업지시서 — 뚝딱툴 블로그 생성기 (Sonnet 5용) v1

> 2026-07-07 · prompt-maker로 생성. 재료: 훅엔진 v2 + 골드샘플뱅크 v1 + blog-publisher-v2 레시피.
> 사이트 서버 프롬프트의 원본이자, 대표가 지금 바로 복붙해 쓸 수 있는 운영형 프롬프트.

---

## 1. 최종 프롬프트 이름
**뚝딱-블로그 v1** (네이버 홈판·검색 노출용 블로그 원고 생성기)

## 2. 이 프롬프트의 목적
사용자(가게·학원·사무소 운영자)가 키워드와 자기 이야기를 넣으면, **fable급 훅(제목·첫문장) + 체류시간을 만드는 본문 + AI 티 안 나는 문장**의 네이버 블로그 원고 1편을 Sonnet 5가 안정적으로 만들게 한다. 목표는 예쁜 글이 아니라 **홈판 클릭·검색 상위노출 확률 최대화.**

## 3. 사용해야 하는 상황
- 뚝딱툴 사이트의 블로그 글 생성 버튼 뒤 서버 프롬프트로.
- 대표·수강생이 Claude에 직접 복붙해 원고를 뽑을 때.
- 쓰지 않는 상황: 병의원·변호사 원고(→ 시즌2 Opus + 규제검수 파이프라인이 담당. 이유: 광고 규제 검수 없이 내보내면 법적 위험).

## 4. 사용자가 넣어야 할 입력값
| 슬롯 | 필수 | 설명 |
|---|---|---|
| `{{업종}}` | ✅ | 예: 필라테스, 카페, 세무사무소 |
| `{{키워드}}` | ✅ | 노리는 검색어 1개 |
| `{{타겟_독자}}` | ✅ | 예: 30대 직장인, 예비 창업자 |
| `{{사용자_이야기}}` | 선택 | 본인 경험·실적·에피소드 (추가란). **없으면 실적 자랑 없이 장면형으로 작성됨** |
| `{{말투}}` | 선택 | 기본: 다정한 -요체 |
| `{{지역}}` | 선택 | 지역 키워드 필요 시 |
| `{{회피_목록}}` | 선택 | 최근 쓴 제목·숫자·장면 (시스템이 자동 주입 / 수동 사용 시 직전 글 제목 3개 붙여넣기) |

## 5. 모델이 수행해야 할 작업 (번호 단계 — Sonnet은 적어준 만큼 깊어진다)
1. `{{키워드}}` 검색자의 의도를 한 줄로 정의한다 (정보형/비교형/사용법형).
2. 제목 후보 3개를 만든다 — 12패턴 중 서로 다른 조합, `{{회피_목록}}`과 골격이 겹치지 않게. 최종 1개 선택.
3. 첫문장을 8뱅크 중 1개로 쓴다 — 구체적 장면·시간·대사 1개 필수.
4. 본문을 4단 구조로 쓴다: 도입(첫문장 확장 2~3문장) → 잘못된 선택 2~3개 → 기준 제시(+`{{사용자_이야기}}` 있으면 여기 녹임) → 댓글 유도 마무리.
5. AEO 처리: 각 소제목 첫 문장에 결론 먼저 · 글 끝 3줄 요약 · FAQ 3개.
6. 태그 5~10개, 이미지 자리 `[IMG]` 6개(소제목마다 1개꼴)를 넣는다.
7. **완료 전 자체검증**: 7번 섹션 체크리스트를 하나씩 확인하고, 통과 여부를 결과 맨 아래 표로 보고한다. 통과 못 한 항목은 고친 뒤 다시 검사한다.

## 6. 출력 형식
```
# 제목 (25자 이내)
본문 (공백 포함 2,000~3,000자 · 소제목 4~6개 · [IMG] 6개)
FAQ 3개
태그: #...
---
[자체검증 표] 항목 | 통과여부
```

## 7. 품질 검증 기준 (복붙 프롬프트 안 체크리스트와 동일)
1. 금지어(방·꿀·비·"하세요" 계열) 0건
2. 제목 25자 이내 + 끝이 명사로 뚝 끊기지 않음
3. 첫문장에 구체 장면·시간·대사 있음
4. `{{사용자_이야기}}` 없는데 실적·경력 숫자가 등장하지 않음 (날조 0건)
5. 같은 종결어미 3연속 없음
6. `{{회피_목록}}`과 제목 골격·핵심 숫자·장면 안 겹침
7. 소제목 첫 문장이 결론 먼저인가 · 3줄 요약과 FAQ가 있는가

## 8. 실패 방지 규칙 (전부 "왜" 포함)
- 실적·경력을 지어내지 않는다 (이유: 여러 사용자가 쓰는 서비스라 거짓 실적은 사용자 신뢰·법적 문제로 직결).
- "망합니다/실패합니다" 같은 확정 표현을 쓰지 않는다 (이유: 부정 어그로는 브랜드 톤 훼손 + 이탈 유발. 경고·후회 톤까지는 허용).
- 출처·URL·매체명을 넣지 않는다 (이유: 인용 표절 시비 방지. 경험·해석으로 재서술).
- 요청 밖 섹션(예: 인스타 캡션)을 덧붙이지 않는다 (이유: 운영형 프롬프트는 출력이 예측 가능해야 파이프라인이 안 깨진다).
- 검증 표에서 실패 항목을 통과로 표시하지 않는다 (이유: 그럴듯한 허위 보고가 가장 위험 — 실패는 실패로 적고 고친다).

## 9. 좋은 예시 (골드뱅크 발췌)
- 제목: "광고를 껐는데 매출이 올랐어요, 학원 얘기입니다" — 반전+구체, 완결형.
- 첫문장: "마감하고 불을 끄기 전에, 오늘도 텅 빈 예약표를 한 번 더 봤어요." — 장면·감각.
- 슬롯 활용: "{{경력}} 원장이 상담 문의를 두 배로 만든 순서예요" — 값 있을 때만.

## 10. 나쁜 예시
- "필라테스 다이어트 방법 총정리" — 금지어+명사 끊김+긴장감 없음.
- "저는 오랫동안 이 일을 해온 사람입니다" — 평면 설명, 장면 없음.
- "14년 경력의 전문가가 알려드립니다" (사용자_이야기 비었는데) — 실적 날조.

## 11. ChatGPT에서 사용할 때 조정법
- XML 태그를 `## 역할` `## 작업` 마크다운 헤더로 바꾼다.
- "각 단계를 건너뛰지 말고 순서대로"를 작업 첫 줄에 추가 (단계 준수가 느슨한 편).
- "출력 전에 검증 기준 7개를 표로 먼저 보여라"로 검증을 출력물에 강제.

## 12. Claude(Opus 4.8·Sonnet 5)에서 사용할 때 조정법
- Sonnet 5: 그대로 사용. max_tokens 여유(새 토크나이저가 토큰 30%↑ — 빡빡하면 답이 잘림). temperature 설정 금지(400 에러).
- Opus 4.8(전문가용 시즌2): effort `high` 이상. 이 지시서에 규제검수는 없으므로 시즌2 검수 패스를 뒤에 붙여야 한다.

## 13. Gemini에서 사용할 때 조정법
- 골드샘플 예시를 3개→5개로 늘린다 (예시 민감도 높음).
- 출력 형식을 표·고정 헤더로 더 기계적으로 (창의적 이탈 방지).

## 14. Claude Code로 넘길 때 조정법
- 서버 이식 시: 출력을 JSON 계약(`{title, body, tags, faq, note}`)으로 바꾸고 파싱은 `parseDraft` 재사용 (시즌2와 동일 구조).
- 자체검증 표는 서버에선 **별도 검수 패스**로 분리 (이유: 생성 프롬프트에 검증을 쌓으면 rule-stacking — 시즌2 원칙).
- `{{회피_목록}}`은 회전 레이어가 DB(사용자별 최근 N편)에서 자동 주입.

2. 제목 후보 3개 — 아래 12패턴에서 서로 다른 1~2개 조합, 25자 이내, 키워드 앞배치. 회피 목록과 골격·숫자가 겹치면 그 후보는 버리고 새로 만든다. 최종 1개를 고른다.

## 검증 로그
- **v1 실전 검증 1건 통과 (2026-07-07, Sonnet 5)**: 입력=필라테스 체험수업 · 사용자_이야기 비움 · 회피목록 3건.
  - 산출 제목 "필라테스 체험수업 받고 왜 울컥했을까요" — 새 골격(감정 각도), 첫문장 장면+대사.
  - 7항목 전부 통과(fable이 직접 재채점 — 자기보고 아님): 금지어 0 · 25자 완결형 · 장면/대사 · **날조 0(빈 슬롯인데 실적 안 지어냄)** · 어미 3연속 없음 · 회피목록 완전 회피 · AEO 3종.
  - 분량 약 2,000자(하한선) — 양산 시 "2,300자 안팎" 지정 검토.
- 남은 검증: 다업종·다회 호출 반복 테스트(회전 레이어 얹은 뒤), 실발행 클릭 데이터.
