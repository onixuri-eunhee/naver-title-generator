## 1. 한 줄 요약

뚝딱툴을 "여러 도구 모음"에서 **"네이버 블로그 + 스레드 글을 자동으로 만들어 올려주는 프로그램"** 하나로 다시 만든다. 숏폼·롱폼은 완전히 뺀다.

---

## 2. 배경 — 왜 다시 만드나

- 버전 1은 도구가 너무 많았다: 제목 생성, 키워드 찾기, 글쓰기, 이미지, 카드뉴스, 후킹 문구, 숏폼, 스레드 글쓰기 등. 기능이 흩어져서 "이걸로 뭘 하는 도구인지" 설명이 어려웠다.
- 숏폼·롱폼은 시즌 2에서 빼고 **나중에 별도 상품으로 다시 오픈**한다. 재오픈 시 처리할 코드리뷰 4건(H1·H2·H3·M1)은 그때 함께 처리.
- 사용자(블로그 마케터·1인 사업자)가 진짜 원하는 건 하나다: **"내 블로그에 글이 자동으로 올라가는 것."**
- 대표가 이미 검증한 파이프라인이 있다: 키워드 리서치 → 크롤링·분석 → 원고 → 이미지 → 네이버 자동 임시저장/발행 (내부 스킬 blog-publisher-v2로 실사용 중). 시즌 2는 이걸 상품으로 만드는 것.
- **판매 근거 = 대표 본인 블로그.** 이 자동화 방식 그대로 키운 블로그의 실제 성과를 증거로 내세워, "같은 방식을 그대로 쓸 수 있는 사용권"을 판다.

## 3. 목표와 성공 기준

### 목표 (이렇게 되면 성공)
1. 사용자가 주제 하나만 넣으면 글+이미지가 완성되고, 원하면 네이버에 자동으로 올라간다.
2. 스레드도 같은 방식으로 글 생성 → 자동 게시·예약까지 된다.
3. 기존 뚝딱툴 결제 회원이 시즌 2로 자연스럽게 넘어온다.

### 안 만드는 것 (Non-Goals) — 이번에 절대 안 함
1. **숏폼·롱폼 영상 기능 전부** — 시즌 2 범위 밖. 코드는 보존, 메뉴에서만 숨김. **나중에 별도 오픈 예정.**
2. **인스타그램·유튜브 등 다른 채널** — 네이버 블로그 + 스레드 두 개만.
3. **제목 생성기·키워드 파인더 별도 페이지** — 시즌 2에서는 독립 메뉴로 안 냄. 로직만 블로그 생성 과정(키워드 리서치·제목 뽑기)에 내부적으로 재활용.
4. **토스페이먼츠 심사 기간 중 기존 페이지 수정** — 아래 제약 조건 참고.

### 성공 지표 (숫자는 대표 확정 필요)

| 지표 | 현재 | 목표 | 측정 방법 |
|------|------|------|----------|
| 주제 입력 → 글+이미지 완성 시간 | (수동 수 시간) | 10분 이내 | 서버 로그 |
| 자동 임시저장/발행 성공률 | — | 95% 이상 | 발행 결과 로그 |
| 글 1편 생성 원가 | 약 2,200원 (확정·아래 참고) | 유지·인하 | API 비용 합산 |
| 발행으로 인한 계정 제재율 | — | 0% 유지 | 사용자 신고·CS |

## 4. 대상 사용자 (전환 — 고단가 B2B)

- **주 타깃: 기업 · 병원 · 변호사(법무법인).** 1인 사업자·소상공인은 주 타깃 아님 (가격대가 안 맞음).
- 상황: 블로그 마케팅이 필요하지만, ①대행사에 월 40~200만원씩 쓰고 있고 ②병원·변호사는 광고 규제(의료광고 심의·변호사 광고규정) 때문에 아무 글이나 못 올림 ③품질 낮은 대행 글로 리스크를 겪음
- 지금 하는 방법: 월 40~200만원 대행 계약 (본 PRD 시세표 참고)
- 시즌 2가 주는 것: **대행사급 품질을 규제까지 지켜서, 대행 몇 달 값의 연 사용권 한 번으로.** 계정당 99만~165만원.
- 왜 이 가격이 되나: 대행사 월 40~200만원을 1년 쓰면 480~2,400만원. 시즌 2 연 사용권 99만~165만원은 대행 2~4개월 값 = 강력한 대체재.

#### 6-1. 노출 전략별 글 작성 프롬프트 — 3벌 분리 (확정)

노출 목표가 다르면 글의 구조 자체가 달라지므로 프롬프트를 각각 만든다:

| 전략 | 글의 성격 | 프롬프트가 강제할 규칙 (핵심) |
|------|----------|------------------------------|
| 홈피드 100% | 관심사·공감형 글 | 첫 3줄 후킹(스크롤 멈춤), 경험담·스토리 중심, 키워드 밀도 낮게, 체류시간 유도(긴 호흡·이미지 배치), 제목은 호기심형 |
| 홈피드 50% : 검색 50% | 혼합형 | 제목·첫 문단에 키워드 배치하되 후킹 유지, 소제목 일부만 키워드형, 스토리+정보 반반 |
| 검색 100% | 정보·검색 최적화 글 | 제목·소제목·본문에 키워드 규칙 배치, 소제목 구조화(질문형), 정보 완결성(비교·표·목록), 검색 의도에 정확히 답 |

#### 6-2. 3가지 전략 공통 적용 (확정) — 전략이 달라도 이건 똑같이

프롬프트는 3벌로 나누되, 아래는 **하나의 공통 모듈**로 만들어 3가지 전략 모두에 동일하게 적용한다:

| 공통 요소 | 내용 |
|-----------|------|
| AI 검수기 | 원고 완성 후 AI가 자체 검수(품질·금지어·표절성·페르소나 일치) → 불합격 시 자동 재작성 |
| 발행 전 체크리스트 | 글 작성 후 항목별 점검표(제목·이미지·키워드 배치·출처 표기 등)를 통과해야 발행 단계로 넘어감 |
| AI 인용 규칙 | AI가 자료(업로드 문서·학술자료·외부 글)를 인용할 때 지켜야 할 법칙 — 출처 표기, 원문 복붙 금지, 근거 없는 주장 금지. 전략과 무관하게 항상 동일 |
| 업종별 광고 규제 검수 (P0·필수) | **병원 = 의료광고 심의 규정 / 변호사 = 변호사 광고규정 / 기업 = 표시광고법.** 업종 선택에 따라 금지 표현(과장·치료효과 보장·최상급·환자 유인 등)을 자동 차단하고, 위반 소지 문구는 발행 전 경고. **이게 없으면 병원·변호사는 못 씀 = 출시 불가 조건** (초안: 04_regulation-check-module.md) |
| AEO — AI 인용 최적화 (P0) | 챗지피티·퍼플렉시티·네이버 AI 등이 우리 글을 답변 근거로 인용하게 만든다. 두괄식 즉답·질문형 소제목·구조화 데이터·FAQ 블록·근거 표기. 3벌 전략에 강도 조절해 공통 적용 (초안: 05_aeo-module.md). 대표 지시(2026-07-03). |

#### 6-3. 네이버 발행 방식 — 발행 도우미 (확정)

네이버는 공식 글쓰기 API가 없어 브라우저 자동화(카무폭스)가 필요. **사용자 PC에 설치하는 "발행 도우미" 방식으로 확정.** (서버 자동화는 아래 이유로 배제)

- **왜 서버 방식이 아닌가**: ①여러 사용자 글이 같은 서버 IP에서 나가면 네이버가 이상 감지 → 계정 저품질·정지 위험 ②사용자 네이버 로그인 정보를 회사가 보관해야 함(유출 책임) ③사용자 수만큼 서버 브라우저 = 비용 폭증.
- **발행 도우미 동작**: 마이페이지에서 설치(맥·윈도우, 사용권 인증키 입력) → 최초 1회 네이버 로그인(정보는 그 PC에만 저장, 회사 미보관) → 웹에서 "발행" 클릭 시 도우미가 카무폭스를 백그라운드로 열어 임시저장/발행 처리 → 결과를 웹에 표시. PC 부팅 시 자동 실행.
- **⚠️ 예약 발행 구조 (헛점 수정)**: 도우미는 사용자 PC에서 돌아가므로 예약 시각에 PC가 꺼져 있으면 발행 불가. → **네이버 글쓰기 화면 자체의 '예약 발행' 기능을 사용한다.** 도우미는 글을 올리는 순간(예약 등록)에만 PC가 켜져 있으면 되고, 실제 예약 시각 발행은 네이버가 수행. 서비스 자체 예약 스케줄러로 PC를 깨우는 방식은 쓰지 않음.
- **⚠️ 설치 파일 서명 (헛점 수정)**: 서명 없는 설치 파일은 윈도우·맥이 "위험한 프로그램" 경고 → 유료 사용자 이탈. **윈도우 코드사이닝 인증서 + 맥 공증(notarization)을 출시 전 필수 확보.** 비용·발급 기간을 일정에 선반영.
- **설치 부담 완화**: ①설치 3분 안내 영상 온보딩 ②설치 없이 쓰려는 사용자를 위한 "완성 글 복사 → 직접 붙여넣기"(수동, 0단계) 항상 제공.
- **스레드는 설치 불필요**: 메타 공식 API로 서버에서 게시·예약 처리.

## 6. 만드는 방법 (큰 그림)

```
[최초 1회 — 마이페이지 세팅]
   페르소나 (내 글/벤치마킹 글 URL 분석)
   + 참고 자료 업로드 (학술자료·내부문서)
   + 씨드 키워드 등록
   ↓
[반복 — 글 1편마다]
① 씨드 키워드 확장 발굴 (네이버 검색광고 + 검색 API)
   ↓ 사용자가 키워드 선택
② 노출 전략 선택 (홈피드100 / 반반 / 검색100)
   ↓
③ 전략별 프롬프트 + 페르소나 + 업로드 자료 → 원고 작성 (AI)
   ↓
④ 썸네일 + 본문 이미지 생성 (AI 이미지)
   ↓ 사용자가 미리보기 확인
⑤ 발행 — 트랙 A: 네이버 임시저장 / 트랙 B: 발행·예약
⑥ 스레드 — 공식 API로 게시·예약
```

- 검증된 원본: 내부 파이프라인(blog-publisher-v2)이 이미 ①~④를 수행 중. 시즌 2는 이를 회원용 서비스로 포장.
- **크롤링(①벤치마킹) 안전 설계 (🔴 8-1 #3 대응):** 상위글 크롤링도 네이버 규정 위반·차단 소지 → ①크롤링 속도 제한·간격 두기 ②우리 서버가 아닌 검색 API 우선 사용, 부족분만 최소 크롤링 ③크롤링 대상은 공개 검색결과·본문 구조만(개인정보 수집 X) ④차단 시 폴백(검색 API 스니펫만으로 벤치마킹). 발행뿐 아니라 크롤링도 계정 보호 장치 적용.
- 네이버 자동 발행(⑤)은 공식 글쓰기 API가 없어 브라우저 자동화 필요 → **사용자 PC 설치형 "발행 도우미"로 확정** (상세 6-3).
- 스레드(⑥)는 메타 공식 API가 있어 서버에서 안전하게 처리 가능.
- **판매 방식 (확정): 기간제 사용권 — 1개월권 · 6개월권 · 12개월권.** **무료 사용 불가** — 무료 체험판·무료 크레딧 없음. 결제는 토스페이먼츠 유지.
- **가격대 (확정): 계정당 99만원 ~ 165만원.** 기간별 구성은 이 범위 안에서 배분 (예: 12개월권 상단, 단기권 하단). 정확한 티어별 금액은 미결 #1.
- **사용량 상한 (확정): 하루 3편 + 월 20편.** 월 합계 상한 병행(원가 방어).
- **사용량 카운팅 규칙 (권장안, 대표 확정 필요 — 미결 #10):**
  · 1편 = **이미지까지 완성된 블로그 원고 1건**. 카운트 시점 = 원고 생성 완료.
  · **재생성(검수 불합격 자동 재작성·사용자 수정 재생성)은 같은 건이므로 무료** — 카운트 안 함. (원가는 회사 부담, 남용 방지 위해 건당 재생성 횟수 상한 예: 3회)
  · **스레드는 블로그 20편과 별도 카운트**(짧고 싸므로 별도 한도 예: 월 60건).
  · 초과 시 **생성 단계에서 차단**(발행이 아니라 생성을 막아 원가 발생 자체를 차단).

#### 참고: 글 1편 원가 (2026-07, 실측 단가 확정)

- 모델 단가(1M토큰): Sonnet 5 $3/$15, Haiku $1/$5.
- **이미지 gpt-image-2 high:** 썸네일 = 정사각 1024×1024 (네이버 썸네일 규격) 289원 / 본문 = 세로·가로 1024×1536·1536×1024 226원. ※정사각이 세로/가로보다 63원 비싸지만 썸네일은 정사각 필수.
- 글 전체(키워드+크롤링+원고+검수+규제, Sonnet 5) ≈ 810원 + 이미지 6장(썸네일 289 + 본문 5×226=1,130 = 1,419) = **편당 약 2,230원.** 이미지가 원가의 약 60%.
- 연간 원가 vs 12개월권(99만~165만): 월 20편 → 연 53만원(넉넉) / 월 40편 → 106만원(양호) / 하루3편 매일 90편 → **238만원(적자)**.
- → **월 20편 상한이면 모든 티어에서 원가가 가격의 절반 이하.** 병원·변호사 현실 사용(월 20편 = 주 5편)은 안 걸림. 월 상한은 헤비 재판매 방어용으로 유지.
- **환불 규정**: 무료 체험이 없으므로 명시 필수 — 예: 결제 후 7일 이내 & 생성 3편 이하 전액 환불. 토스 심사·전자상거래법 정합성 확인.
- **사용권 만료 후 데이터**: 만료 시 페르소나·업로드 자료·글 보관함은 즉시 삭제하지 않고 일정 기간 보관 → 재결제 시 복구(갱신 유도). 보관 기간은 미결.

#### 참고: 블로그 대행 시세 (2026-07 네이버 블로그·카페 실검색)

| 방식 | 가격대 | 조건 |

## 8-1. 빠진 곳 점검 (2026-07-04) — 심각도순

전체 PRD 정독 후 발견한 미비점. 🔴=출시 전 반드시 / 🟡=출시 전 권장 / 🟢=출시 후.

### 🔴 1. 데이터 보안·개인정보·기밀 (제일 심각)
- 사용자가 업로드하는 "내부문서"에 **환자 진료정보·변호사 사건자료** 등 민감·기밀 정보 가능. 이걸 외부 AI API(Claude·OpenAI)로 보내면 **개인정보보호법·변호사 비밀유지의무** 문제.
- 필요: ①업로드 자료에 민감정보 넣지 말라는 안내·필터 ②AI API의 데이터 미학습·미보관(zero-retention) 계약/옵션 확인 ③업로드 자료 서버 암호화·보관기간 ④개인정보처리방침에 명시.
- → 미결로 승격.

### 🔴 2. 사용량 카운팅 규칙 미정의 (원가 방어 핵심인데 규칙 없음)
- "하루 3편 + 월 20편"만 정함. **뭘 기준으로 세는지 없음**: 생성 기준? 발행 기준? 재생성(검수 불합격 재작성)도 1편으로 셈? 스레드도 이 20편에 포함? 초과 시 생성이 막히나 발행이 막히나?
- 원가가 이 규칙에 달렸으니 반드시 정의. 권장: **"이미지까지 완성된 원고 1건 = 1편, 재생성은 무료(같은 건), 스레드는 별도 카운트, 초과 시 생성 차단."**

### 🔴 3. 크롤링(벤치마킹) 합법성·차단 리스크 누락
- 상위글 크롤링을 Camoufox로 하는데, 제약 조건엔 "발행" 리스크만 있고 **크롤링 리스크 없음**. 네이버 크롤링 차단·이용약관 위반 소지. 크롤링도 속도 제한·차단 대비 필요.

### 🔴 4. 이미지 규제 검수 누락
- 규제 검수(04번)는 **텍스트만** 봄. 그런데 의료법 제56조②5는 "수술·시술 장면 노출" 금지 = **이미지 규제**. gpt-image가 시술 장면을 그리면 텍스트 검수를 통과해도 위반. 이미지 생성 프롬프트 단계에서 금지 지시 + 생성 후 이미지 검수 필요.

### 🟡 5. B2B 결제·세금계산서
- 타깃이 병원·법무법인(사업자) → **세금계산서 발행 필수.** 토스 유지라지만 B2B 결제·세금계산서·현금영수증 처리 언급 없음.

### 🟡 6. 성공지표에 사업지표 없음
- 지금 지표는 완성시간·발행성공률·전환율뿐. B2B 유료 상품이면 **월 매출(MRR)·사용권 갱신율·객단가·CAC**가 핵심인데 빠짐.

### 🟡 7. 다계정·인증키 도용 방지
- 사용권 1개를 여러 명이 공유하거나 인증키 탈취 시 대응 없음. 동시 사용 제한·기기 수 제한·인증키 재발급 정책 필요.

### 🟡 8. 온보딩·고객지원(CS)
- 병원·변호사는 IT에 약할 수 있음. 설치 3분 영상은 있으나 **CS 채널·설치 원격지원·문의 응대 체계** 없음. 고단가 상품이라 CS 품질이 갱신율에 직결.

### 🟢 9. 네이버 계정 정지 시 사용자 대응
- 성공지표는 "제재율 0%"지만, 만에 하나 정지되면 사용자 보상·책임 범위. 약관(07번)은 광고 규제만 다룸 → 블로그 계정 관련 면책도 추가.

### 🟢 10. "계정당" 정의
- "계정당 99만~165만원"에서 계정 = 사람? 네이버 블로그 1개? 법무법인이 변호사 5명 블로그를 쓰면? 여러 블로그 관리는 P2지만, 1 사용권 = 1 블로그인지 정의 필요.
